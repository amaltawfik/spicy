# i18n stage 2 -- what shipped, what needs Amal, what is left

Branch `i18n2-013`. Stage 1 (the single English registry, R/i18n.R) was
already in. This lot adds the API decision 1 settled and the French set.

## The terminology is settled; the read-through is not

**Decision 38 (2026-08-23) arbitrated all fourteen terminology calls.**
Ten stand as written; four were corrected on this branch. The rule Amal
applied is a clean one and is worth stating, because it will settle the
next set too:

* **francise where French has a term of authority** -- `SD` -> `ET`,
  `SMD` -> `DMS` (Cochrane France), `IQR` -> `EIQ`, `Freq.` -> `Eff.`
  and `Overall` -> `Ensemble` (INSEE), `PSU` -> `UPS`, `calibrated` ->
  `calé` (calage sur marges, INSEE / CALMAR), the outcome ROW ->
  `Variable dépendante` (socio / psy usage), the Excel sheet ->
  `Variable étudiée`, `(rescaled)` -> `(normalisée)`;
* **keep the international term of art** -- `ES`, `hazard ratio`, the
  `Hurdle` of a hurdle component (parenthetical in French: `Hurdle
  (zéro)`), and `Array`, which is an R class name and so falls under the
  same policy as a frozen column name.

`spicy_labels()` stays exported: key discoverability for
`options(spicy.labels)` is worth the pre-1.0 surface.

**What is still owed: a read-through of the other 209 strings.** The
fourteen calls were the ones I could name; a sentence that is merely
awkward does not announce itself, and nobody but a native reader will
catch it.

The full `key -> en -> fr` table, with a status for every one of the 325
keys, is generated by `scratchpad/gen_review.R` and was handed over as
`i18n_fr_review_table.md`. Its terminology block now records each call as
ARBITRATED with the outcome.

Two pairs must move together if either half changes:
`row_missing_level` / `row_missing_level_dedup`, and `row_overall` /
`note_outcome_overall` (the second quotes the first in its sentence).

Deliberately NOT in NEWS: NEWS says what a user can do, not what a
maintainer still owes.

## The display / frozen split, and how it was decided

| Status | Count | How it was decided |
| --- | ---: | --- |
| translated | 208 | a display string with a frozen twin, or no twin at all |
| kept: term of art | 3 | decision 38 -- `ES`, `hazard ratio`, `Array` |
| kept: condition message | 1 | `note_model_prefix` -- error text, see below |
| same in French | 36 | the French word IS the English one; the fallback serves it |
| same in French (confirmed) | 1 | `excel_sheet_continuous` -- checked, not forgotten |
| frozen: notation | 24 | `symbol_*`, `marker_*`, `cell_undefined` -- the registry's own "frozen, never translated" sections |
| frozen: template | 19 | the value is holes and punctuation, no word to translate |
| frozen: column name | 33 | translating it would move a public `as.data.frame()` column name |

The first four follow the registry's own comments. The fifth is the one
that took a decision.

**Why 33 keys are frozen.** In the descriptive families the column name
and the header are two layers: `.CAT_KEY_*`, `.CON_KEY_*`, `.LM_KEY_*`
are frozen literals in the source, and the header beside them comes from
the registry. Those families translate freely, and `test-i18n.R` already
pins each couple at the English default.

`table_regression()` has no such twin. `regression_render.R` builds
`col_name = make_unique_col_name(out, header)` from the very string the
reader sees -- its own comment says so:

> In this family the interval header IS the column's programmatic name
> ... there is no frozen-key twin here, unlike the descriptive families.

So `B`, `SE`, `p`, `95% CI`, `OR`, `AIC`, `Adj. R2` and their siblings
are what `as.data.frame()` publishes. Translating them would move the
contract under an option, which is what decision 1 forbids. They stay
English; the rest of a French regression table -- title excepted, see
below -- translates: row labels, block captions, reference annotations,
fit-statistic rows, every note and gloss.

**The one column name that does follow the language** is the one built
from a LEVEL: `.cat_key_n(g)` pastes `" n"` onto a `by` level, and
spicy's own `(Missing)` category is one of those levels, so a French
table names the column `(Manquant) n`. That is the right side of the
line: a level is data-shaped content, and a French dataset's own levels
already give French column names today. A level named `"Yes"` still
gives `"Yes %"` under `"fr"` -- pinned in `test-i18n_language.R`.

## Follow-ups, in the order I would take them

1. **Split `col_name` from `display_label` in `.regression_column_spec()`**
   (`regression_render.R:938`). One assignment site, but ~25 spec
   entries would need an English twin of `header_short`, plus the
   `model_exp_headers` / `model_stat_headers` paths. Unblocks 33 keys at
   once -- `IC a 95 %`, `RC`, and the interval bounds. Sized as its own
   lot, not a rider on this one.

2. **The regression title and model description are not in the
   registry.** `glm_compute.R:36` and `regression_frame_fixest.R:410`
   hold `"Logistic regression"` and its siblings as literals, so a
   French regression table prints an English title and an English
   `Note.` line. Visible in the snapshot corpus, deliberately. This is a
   stage-1 census gap, not a stage-2 one: it needs new keys.

3. **`cross_tab()` has no display-label layer for its row-identifier
   column.** `freq_print.R:193` maps the frozen name `"Values"` to
   `label_values`; `cross_tab()` prints the column name directly, so
   `freq()` says `Valeurs` and `cross_tab()` says `Values` in the same
   French document. The fix is a display layer in the printer, and it
   has to carry the `Values_1` collision suffix with it.

4. **`reference_label = "(ref.)"`** (`regression_render.R:65`) is an
   argument default, so a French user can pass `"(ref.)"` themselves --
   but the default cannot follow the language.

5. **`note_model_prefix` is misfiled in the registry.** The registry
   header says conditions are deliberately excluded -- they are read by
   developers and quoted in bug reports -- but this key reads like a
   table note and is in fact the lead line of a `spicy_abort()`
   (`regression_frame_geepack.R:182`, `.gee_refuse_cluster()`).
   Translating it gives "Modele 1 : `cluster` is not used for `geeglm`
   models.", a French head on an English body. Left English in the set
   and pinned by a test; the clean fix is to take the key out of the
   registry and inline the prefix at the call site, which moves the
   English registry and so belongs to its own lot.

6. **`varlist-values.R:409` writes `"<NA>"` as a literal** where
   `:258` reads `marker_na`. Harmless today (they are the same string),
   and it would print two different NA markers in one table the day
   `marker_na` moves. One-line fix, deliberately not taken here.

## Incidental findings from the leak audit

The audit walked all 596 `spicy_str()` / `spicy_fmt()` call sites. Two
were live breakages under a translation and are fixed on this branch:

* `inline.R:210` stripped a hardcoded `":$"` off the factor-header cell.
  The colon is written by `label_block_header`, which takes a no-break
  space in French; `trimws()` does not remove it, so addressing a
  variable by its displayed label would have aborted with "no such
  variable", in one language only. Now derived from the template.

* `regression_dispatch.R:184, 822, 1459` strip a model prefix with a
  hardcoded `paste0(lbl, ": ")` written by `header_model_prefixed`.
  Neutralised for now because both that key and `label_model_name` are
  frozen -- but it becomes a live bug the day follow-up 1 lands, and the
  fix belongs in that lot.

Two more that are sound today and would not survive a careless
translation, now covered by tests rather than by luck:

* `.companion_header_pattern()` alternates over `header_se` / `header_p`
  and would silently reclassify any column whose header collided with
  one of them.
* `regression_titlefooter.R:630` looks a gloss up BY header value;
  `setNames()` accepts duplicates and `[[` returns the first, so two
  `header_exp_*` keys collapsing to one French string would print the
  wrong gloss with no condition raised. (`HR` and `RR` both wanting
  `rapport de risques` is the realistic collision.)
